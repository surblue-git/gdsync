# GDSyncの同期安定化とVault直下モードの実装計画

検討日: 2026-09-20。対象: v0.8.1 / `36c4600`。以下は検討時の設計と、その後の実装記録。
既存の同期中表示・手動同期サマリー（`276a4ca`）を前提にする。

## 方針

Driveの対象フォルダと、各端末のVaultルートの対応を一致させる「Vault直下モード」を追加する。
デスクトップはGoogle Drive for Desktop、スマートフォンとGDSyncを使うノートPCは専用Vaultを使う。
全端末で `Notes/note.md` と `Attachments/image.png` が同じVault内パスになる構成を標準とする。
本文は端末間で同一に保ち、送受信のたびにパスを書き換える方式は採用しない。
オンデマンド取得は維持する。既存のサブフォルダモードは互換性のため残し、自動では切り替えない。

直下モードだけ先に追加すると、既存ローカルファイルの誤認や設定変更中の同期をVault全体へ広げる。
先にデータ保全・再試行・完了判定を修正し、その後に直下モードと移行機能を公開する。

追加の回帰対象:

- ダウンロード中のユーザー編集、ロック取得待ちの間のdirty変更、競合コピー作成中の再編集を上書きしない。
- フルスキャンの同名連番が列挙順に依存し、差分処理の衝突処理とも一致しない。Drive IDとの対応を安定化する。端末間で意味が一致しない名前は診断に出す。
- 除外設定変更で「リモートに存在しない」と判断しない。現在の同名baseFolderセグメント除外は直下モードの安全策として流用しない。
- リモートフォルダ削除でインデックス外のローカルファイルまでまとめてゴミ箱へ移動しない。
- インデックス再作成やアプリ停止中に作られたファイルを起動時に照合する。createイベントだけに依存しない。
- 空ファイルの正当な編集と未取得スタブを、サイズではなく管理状態で区別する。

## 実装する構造

### 1. 同期状態と再試行

`SyncCoordinator` を導入し、手動・起動・復帰・フルスキャン・移行の入口を統合する。
通常の転送は並列数を制限し、同じファイルとフォルダ作成はそれぞれ直列化する。
構造変更・移行は関連する転送の終了を待つ。外部から渡されるパスのロックだけに頼らず、操作ID・Drive ID・対象世代で古い処理を識別する。
除外・同期対象の検証はイベント入口だけでなく、実際の読み書き直前にも行う。

ファイルにはローカル編集世代と送信済み世代を持たせる。
送信開始時に内容と世代を捕捉し、成功しても送信した世代だけをACKする。
読み取り中や通信中に世代が進んだ場合は未送信を残す。
新規ファイル・フォルダのPOST応答喪失は単純再作成せず、永続操作IDとDrive側照合で回収する。
利用するDriveメタデータ/APIの可否とデスクトップ経由の置換時の挙動は実装時に検証する。

受信差分は「取得済み」と「ローカル適用済み」を分離する。
差分と次の取得位置を同じ永続状態として確定してから適用する。失敗分は残して再試行する。
再実行しても結果が重複しないよう、現在のDriveメタデータとの照合を行う。
親未解決・パス衝突は黙って捨てず保留にし、後続の差分で無効になった操作も整理する。
フルスキャンはこの保留状態と整合させて実行する。

### 2. 完了判定と既存通知

表示は現在の `StatusDisplay` を拡張する。判定の正本はCoordinatorが返す `SyncResult` と永続状態に置く。
booleanで「成功」と「再試行不要」を兼用しない。

結果は `complete / pending / partial / blocked / failed` を区別し、次を含める。

- 成功した送受信数、未送信ファイル数、未処理構造変更数、未適用差分数。
- 競合コピー数、添付の未送信数、解決が必要な参照数。
- 開始・終了時刻、最終試行時刻、最後に成功した時刻、停止理由。

「同期完了」は、この端末で対象世代の送信・構造変更・取得済み差分の適用と永続化が終わった場合だけ表示する。
同時に新しい編集が入ったら「今回の対象は送信済み・新しい編集が送信待ち」と表示する。
オフライン時は再試行を無期限に待たず、「未送信2件・接続後に再試行」と返す。
「変更なし」はスキャン未実施・通信失敗・未送信保留と区別する。
この表示は他端末への到着保証ではない。表記上も「Driveとの同期」と範囲を明確にする。

実行中転送はサイクル終了で消さない。同名ファイルは操作IDで別々に管理し、表示には必要に応じて相対パスを使う。
デスクトップのステータスバー、モバイルの長時間通知、手動同期のサマリーは維持する。
設定画面にも同じ結果を表示し、未送信がある限り成功色・完了文言へ戻さない。

### 3. Vault直下モード

設定に `mountMode: subfolder | vaultRoot` を設ける。空欄を特別扱いするだけの実装にはしない。
パス変換と対象判定を独立したモジュールに集約する。インデックス内のパスは引き続きDriveルート相対とする。
Vaultルート、Driveルート、表示用パスを明確に分け、ルート自体はリネーム・削除操作の対象にしない。

直下モードでは `toVault('Notes/a.md') === 'Notes/a.md'` とする。
サブフォルダモードでは `toVault('Notes/a.md') === 'GDrive/Notes/a.md'` を維持する。
Vault外パス、`..`による範囲逸脱、OS絶対パスは拒否し、大小文字・Unicode・禁止文字による衝突を照合する。

`app.vault.configDir`、`.obsidian`、`.trash`、`.nomedia`、移行管理データ・退避データをユーザー除外設定とは別に保護する。
`.nomedia` はAndroidのVault直下にも作れるよう変更する。
現在の `isActive()`、設定入力、接続コード検証、`ensureNoMedia()`、ベース自体のrename処理をすべて対応させる。
ローカル配置・同期有効化は端末固有とし、接続コードから稼働中の配置を即時上書きしない。
旧接続コードも読めるが、初期設定の提案として扱い、既存のマウントには移行手順を通す。

### 4. 添付とリンク

同期対象ノートの参照を解析し、ローカル添付について実体・同期範囲・送信状態を確認する。
外部HTTP URL、見出し、ブロック参照、コード内文字列を画像ファイルと誤認しない。
同期外の画像を黙って収集・移動せず、参照元とコピー先を示した修復候補にする。
新規ローカル添付を優先送信し、その世代が送信済みになってから参照元の新規内容を送る。
添付失敗時もノートの編集内容はローカルへ保存し、依存待ちとして表示する。
通常ノート同士のリンクをすべて依存待ちにすると循環するため、依存制御は必要な添付に限定する。

受信時には、本文解析の時点で画像スタブがまだないケースを再評価する。
後から画像の差分が到着した時、開いているノートの参照先を再取得して表示を更新する。
既に表示した画像のリモート更新も鮮度確認対象にし、開いているノートが使う添付はキャッシュ解放から保護する。
サイズ上限超過は失敗や参照切れと分けて表示する。

### 5. 移行

既存利用者はそのままサブフォルダモードで起動する。移行は事前診断→保全→配置変更→参照修復→検証→有効化の順に行う。

1. 同期元ID、ローカル配置、未送信編集、構造変更、同期外添付、移行先の同名ファイル、スタブを一覧化する。
2. 通常同期を静止させ、実行中操作を待つ。未送信本文・画像と旧インデックスを保全する。移行中の新規編集も検知し、そのまま有効化しない。
3. 移行ジャーナルに操作と完了位置を保存する。移行先に未知のファイルがあれば上書きしない。ローカル配置変更をDriveの削除・renameとして送らない。
4. 既存の `GDrive/...` 参照は旧参照先が一意に確定したものだけ変換する。リンクの位置情報・本文世代を確認し、正規表現による一括置換を避ける。
5. 未取得ノートは、本文を取得しないとリンクを検査できない。全件の検証完了を主張する移行は、Markdownと対応するCanvas等を取得・検査する。遅延検査を選ぶ場合は未検査件数を表示する。
6. Markdown以外の参照は形式別に扱う。未知のプラグイン独自形式は自動修復済みとしない。短縮名で候補が複数あるものも保留する。
7. ファイル数・Drive ID対応・実内容のハッシュ・リンク・未送信状態を検証後、新しいマウント設定とインデックスを確定する。再起動後は未完了移行から再開する。

退避はインデックスだけでは不十分。修正前の実内容も保全する。
他端末が旧構造のまま編集すると旧プレフィックスを再挿入できるため、移行対象のGDSync端末をそろえる運用が必要。
初版の移行範囲は単一Driveルートの専用Vault。複数マウントや混在Vaultの無条件統合は対象外とする。

## 実装順と合格条件

| 段階 | 内容 | 主な回帰テスト |
|---|---|---|
| A | 編集世代、送信キュー、差分永続化、ファイル保全、フォルダ作成、保存直列化 | 自動送信後の同名パス再送、読取後の編集、受信失敗後の再起動、未知の実ファイル、同時フォルダ作成、API成功後の応答喪失 |
| B | CoordinatorとSyncResult、既存通知の統合 | 手動・自動・スキャンの重複、失敗時の未送信数、同名ファイル並列、認証切れ、連続編集中の終了、再試行待ちからの復帰 |
| C | 直下モードと同期対象固定 | ルートの変換、保護対象、同期中の設定変更、旧設定・接続コード、Android `.nomedia`、除外変更、起動時ローカル照合 |
| D | 添付整合性と移行 | Android画像挿入→Drive→デスクトップ、逆方向、添付の遅着、サイズ制限、重複名、日本語・空白、旧プレフィックス、移行途中終了からの再開 |

ユニットテストはタイマー・Drive・Vaultを制御した再現テストを中心にする。
統合テストは破棄可能なDriveフォルダと専用テストVaultで行う。
実機ではデスクトップ・ノートPC・Androidの三端末で、ネットワーク断・アプリ終了・同時編集・移動・削除・競合コピーを確認する。
成功条件は表示だけではなく、各端末のファイル内容・パス・保留状態・Driveの重複ファイル有無で判定する。
既存のオンデマンド取得、空スタブ送信防止、競合コピー、eager取得、キャッシュ解放を回帰対象に含める。

## 実装記録（2026-09-21）

- 同期エンジン内でキューの静止・実行中処理の待機・スキャン排他を統合。送信待機は試行単位、同時実行数は3。手動・自動とも現在の対象を一度試行し、再試行はバックグラウンドへ残す。
- 編集世代とローカルstatの照合、受信差分の永続化、フォルダ作成の共有Promise、Driveの事前生成ID、同期記録の直列保存とチェックポイント復旧を実装。
- 送信中のリネーム・削除を反映し、旧パスの再登録を防止。競合コピーは送信前にローカルへ保存する。
- 既存の通知・ステータスバーを維持し、転送ごとの識別、未完了の件数表示、最終試行と成功日時の分離を実装。
- `sync-paths.ts` にパス変換・保護対象を集約。新規設定はVault直下、既存設定はサブフォルダ方式。接続コードによる既存同期先の上書きを停止。
- 添付診断と依存先の優先送信、更新後のメタデータ待ち、開いたノートの添付再取得を追加。
- `mount-migration.ts` にローカル内容の退避・ハッシュ検証・移行記録・中断再開を実装。Markdown本文の解析済みリンクとCanvasファイルノードを変換する。
- 33件の回帰テストを追加。実機・実アカウントへの書き込みや既存Vaultの移行は、この開発作業では実行していない。

実装上の境界:

- 移行は専用Vault向け。既存の移行先ファイルや移行中の編集を検知した場合は、内容を保護して停止する。自動上書き・曖昧なリンクの推測修復はしない。
- frontmatterのリンクは報告のみ。独自プラグイン形式・Canvasテキストノード内リンクは対象外。未取得のMarkdown/Canvasは移行時に取得する。
- 同名・禁止文字によるDriveパス衝突は、差分適用で保留しフルスキャンで再検証する。すべてのプラグイン固有パスや全端末での同時編集を完全に調停する仕組みではない。
- Driveへの通常更新は従来のチェックサム競合検知を維持する。別端末がチェックと送信の間に同時更新する場合の原子的な排他は未実装。実機での競合テストは引き続き必要。
- 通知はこの端末とDriveの処理結果であり、Google Drive for Desktopや別端末への配送完了を意味しない。

# GDSync 0.9.2 同期滞留の復旧

## 更新と確認

1. PC・Androidで編集中の内容を保存する。AndroidのGDSyncを無効化し、Obsidianを完全終了する。AndroidのVaultをコピーしてバックアップする。特に `GDrive`、`.obsidian/plugins/gdsync`、Writing Ex台帳と競合コピーを保管する。
2. AndroidでObsidianを起動し、GDSyncを無効のままBRATから0.9.2へ更新する。手動更新の場合はObsidian終了中に `main.js`、`manifest.json`、`styles.css` のみ差し替える。`data.json`、`index.json`、バックアップ、ノートは保持する。
3. バージョン0.9.2を確認してGDSyncを有効にする。起動時の同期が自動復旧を試みる。設定の「同期の詳細」で処理段階、経過時間、未送信・未適用差分、失敗理由を確認する。「同期」を押した際も進行中の詳細が表示される。
4. 接続が安定した状態で同期を完了させ、未送信・構造変更・未適用差分が0件であることを確認する。残った場合は「同期の詳細」と新しい `index.json` で原因を確認する。リセットによる消去は不要。

## 復旧の条件と保全

- 旧記録でDrive IDがなく、初回登録のまま、0バイトの実体・ハッシュを持ち、Driveに同じパスの本文があるファイルのみ空スタブ復旧の候補とする。Drive側も空の場合はハッシュが一致したものだけ対応を戻す。
- 現在の実体を再確認し、`.obsidian/plugins/gdsync/stub-recovery` に元内容と元登録情報を保存・読み返して検証してからDrive IDを戻す。退避に失敗した場合は復旧を止める。
- 0.9.2で新規作成した空ファイル、編集中に内容が変わったファイル、既存の競合は自動で置き換えない。復旧中の編集も保持する。
- ダウンロード失敗は差分と復旧待ち状態を残し、次の同期で再開する。サイズ上限を超えるファイルはIDを復旧したスタブとして保持する。
- 同じ名前の別Driveファイル・フォルダは `(Drive ファイルID)` を付けた別名で保持する。Drive上の原本を変更しない。
- 除外フォルダの子孫は差分を適用せず処理済みにする。親フォルダの照会は同一同期内で共有する。
- 取得済みでローカル編集のない本文は、開いていなくてもDrive差分を反映する。Writing Ex台帳もこの対象になる。

## 通信待ち

Driveの読み取りとOAuth更新は60秒で応答待ちを終了する。遅れて届いた読み取り結果は適用しない。Driveへの書き込みは結果不明のまま重複実行しないため、時間だけでロックを解除しない。書き込み待ちの場合は処理段階・対象ファイル・経過時間を表示する。

## 検証の範囲

自動テストで復旧、バックアップ失敗、編集中の保護、再開、除外配下、同名ファイル・フォルダ、台帳更新、読み取りタイムアウトを検証した。添付されたAndroidの保存記録は変更せず、メモリ内で再現を行った。実Android・実Driveで残件数が0になることは更新後の確認が必要。
